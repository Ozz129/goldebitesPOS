2. Despliegue estándar (cambios de código)

1

Verificar en local antes de subir

Antes de comitear: typecheck de ambos proyectos, build de ambos, y la suite de tests del backend.

# Backend
cd GB-BE && npx tsc --noEmit -p tsconfig.json && npm test && npm run build

# Frontend
cd GB && npx tsc --noEmit -p tsconfig.json && npm run build
2

Commit y push

git add -A
git commit -m "mensaje descriptivo"
git push origin main
3

Conectarse al servidor y traer los cambios

ssh -i ~/.ssh/golden_bites_oracle ubuntu@157.137.220.21
cd /opt/golden-bites/app
git pull origin main
4

Reconstruir las imágenes que cambiaron

Solo reconstruye lo necesario: si solo cambió el frontend, basta con frontend; si cambió el backend (o ambos), incluye backend.

sudo docker compose -f docker-compose.prod.yml build backend frontend
5

Reiniciar los contenedores

sudo docker compose -f docker-compose.prod.yml up -d backend frontend
Nota esperada Docker mostrará advertencias "DB_NAME"/"DB_USER"/"DB_PASSWORD" variable is not set — es inofensivo (no existe un archivo .env de nivel superior para la interpolación de esas variables en el YAML; el backend igual carga sus credenciales reales desde .env.production vía env_file). También es normal que postgres aparezca como Recreate: sus datos viven en el volumen golden_bites_pg_data, no en el contenedor, así que no se pierden.
6

Correr migraciones nuevas de base de datos (si las hay)

El runner es idempotente: las migraciones ya aplicadas se saltan automáticamente.

sudo docker compose -f docker-compose.prod.yml exec backend node dist/database/migration-runner.js
7

Verificar que todo quedó sano

curl -s -o /dev/null -w "frontend: %{http_code}\n" http://goldenbites.duckdns.org/
curl -s -o /dev/null -w "api: %{http_code}\n" http://goldenbites.duckdns.org/api/v1/health
sudo docker compose -f docker-compose.prod.yml ps
sudo docker compose -f docker-compose.prod.yml logs backend --tail 30

Ambos curl deben devolver 200, y los tres contenedores deben verse Up (postgres además healthy).

4. Rollback (revertir un despliegue problemático)

1

Volver al commit anterior en el servidor

cd /opt/golden-bites/app
git log --oneline -5              # identificar el commit bueno anterior
git checkout <hash-del-commit-bueno>
sudo docker compose -f docker-compose.prod.yml build backend frontend
sudo docker compose -f docker-compose.prod.yml up -d backend frontend
Cuidado con las migraciones El runner de migraciones no tiene "down" automático. Si el despliegue problemático incluía una migración de base de datos, revertir el código no revierte el esquema — hay que evaluar caso por caso si la migración es segura de dejar aplicada o si se necesita un script manual de reversión. Cuando termines de investigar, vuelve a git checkout main para no quedar en un HEAD desprendido.
