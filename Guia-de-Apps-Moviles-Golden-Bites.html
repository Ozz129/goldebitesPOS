1. Qué hay

AppNombre en el celularPara quiénQué hace
MeseroGB MeseroMeserosTomar pedidos, ver mesas activas, mostrar la carta, avisos de mesa que pide ayuda y pedido listo.
DomiciliosGB DomiciliosDomiciliariosDomicilios asignados, ruta y mapa, chat y llamadas, y ubicación compartida también con el teléfono bloqueado.

Las dos son el mismo POS, empaquetado para el celular; cada una trae solo su parte. La versión web sigue igual. Los instaladores (archivos .apk) quedan en GB/apks/; su nombre dice la app y la versión, por ejemplo GB-Domicilios-staging-v1.0.8.apk.

2. Usuarios de prueba

Las apps se conectan a un servidor; cada servidor tiene sus propios usuarios. Arriba del inicio de sesión de la app se ve a cuál está conectada.

Staging — servidor de prueba en internet

Funciona desde cualquier lugar con internet. POS web: https://staging.goldenbites.net

Local — el computador de desarrollo

Funciona solo con el celular o tablet en el mismo Wi-Fi que el computador y con el servidor del POS corriendo en él (npm run start:dev en GB-BE). Dirección en la app: http://192.168.80.31:3000/api/v1. POS web: http://localhost:5173 (en el computador).

No hay usuarios de prueba en producción: las cuentas son de personas reales. Para probar allá, crea desde el POS de producción (Empleados) un mesero y un domiciliario de prueba. Todo lo que se haga en producción es real.

3. Instalar las apps y entrar

1

Pasar el instalador al celular o tablet

Envía el .apk por WhatsApp, Google Drive o cable. Toca el archivo y luego «Instalar». La primera vez, Android pregunta si permites instalar apps «de origen desconocido» desde esa app: di que sí.

2

Elegir el servidor (función oculta)

En el inicio de sesión, arriba dice STAGING (naranja), LOCAL (azul) o nada si es producción. Para cambiar: toca 3 veces seguidas el logo de Midas Tech (abajo), elige Local, Staging o Producción y toca «Conectar». La app se reinicia en ese servidor y cierra la sesión. En Local, la dirección del computador ya viene escrita (se puede editar).

3

Entrar y activar las notificaciones

Entra con el usuario de ese servidor (sección 2). Arriba aparece «Activa las notificaciones…»: toca Activar y luego Permitir.

Las notificaciones, por ahora Las notificaciones tipo WhatsApp (el aviso que cae desde arriba y queda en la barra) aparecen con la app abierta. Para que también lleguen con la app cerrada o el teléfono bloqueado falta configurar Firebase (sección 6).

6. Notificaciones con la app cerrada (Firebase)

Hoy cada app muestra sus notificaciones mientras está abierta. Con la app cerrada o el teléfono bloqueado, las manda el servidor por Firebase (así funciona también WhatsApp). Para activarlo, una sola vez:

  1. En console.firebase.google.com, crea un proyecto (gratis).
  2. Agrega dos «apps Android»: net.goldenbites.mesero y net.goldenbites.domiciliario. Descarga google-services.json (sirve para las dos) y ponlo en GB/android/app/ y en GB/android-domiciliario/app/. Después genera los APK nuevos.
  3. Configuración del proyecto → Cuentas de servicio → «Generar nueva clave privada». Es secreta: su contenido, en base64 y en una sola línea, va en FCM_SERVICE_ACCOUNT del .env del servidor (staging y producción).

Qué avisa cada app: Mesero — mesa que pide ayuda, pedido listo. Domicilios — nuevo domicilio, mensaje del restaurante o del cliente, llamada, pedido listo para recoger, domicilio cancelado, domicilio reasignado y recordatorio si lleva 10 minutos sin salir.

7. Probar en tu tablet o celular con cable

1

Activar el modo desarrollador (una vez)

Ajustes → Acerca de la tablet → Información de software → toca 7 veces «Número de compilación». Vuelve a Ajustes → al final, Opciones de desarrollador → activa Depuración USB (o busca «depuración» con la lupa de Ajustes).

2

Conectar

Conecta el cable USB de datos. En la tablet acepta «¿Permitir depuración USB?» con «Permitir siempre desde este equipo». Si Windows no la reconoce, instala el «Samsung Android USB Driver».

3

Instalar desde Android Studio

En una terminal, en la carpeta GB: npm run mesero:android y luego npm run mesero:open (o domiciliario:android y domiciliario:open). En Android Studio elige la tablet arriba y toca ▶. Abajo, «Logcat» muestra los errores en vivo. Si sale un error con «major version 69»: File → Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK → jbr-21.

Sin celular: en Android Studio, Device Manager → ▶ en «Medium Phone»; arrastra el .apk sobre la ventana para instalarlo. Para simular movimiento del domiciliario: «⋯» (Extended controls) → Location.

8. Sacar una versión nueva

Qué cambióQué hacer
Solo el servidor (GB-BE)Desplegar. Las apps instaladas lo usan de una vez.
Pantallas (GB) o algo de AndroidGenerar un APK nuevo e instalarlo encima.

En la carpeta GB:

npm run apk:mesero          # app de mesero
npm run apk:domiciliario    # app del domiciliario

Tarda alrededor de un minuto y deja el archivo en GB/apks/. Cada APK sube la versión solo, así que se instala encima del anterior sin perder la sesión. Genera los APK siempre desde el mismo computador: uno hecho en otro no se instala encima (habría que desinstalar primero).

Para desarrollar con cambios al instante: npm run dev:mesero (o dev:domiciliario) y, una vez, npm run apk:mesero:local (o apk:domiciliario:local). Ese APK carga las pantallas desde el computador: cada cambio guardado se ve en el celular sin generar otro APK.

9. Si algo falla

Qué pasaQué revisar
«No fue posible conectar con el servidor»Staging: internet en el teléfono y los cambios de las apps desplegados en staging. Local: servidor corriendo en el computador, mismo Wi-Fi, dirección correcta y que Windows permita a «Node.js» usar la red (redes privadas).
«Correo o contraseña incorrectos»El usuario debe ser del servidor que dice arriba (STAGING o LOCAL).
«Este usuario no puede tomar pedidos» / «no es domiciliario»Se entró con el usuario de la otra app. Tocar «Cambiar de usuario».
No aparece la notificaciónQue se haya tocado «Activar» y «Permitir». Sin Firebase, solo aparece con la app abierta.
«Sin permiso de ubicación»Tocar ese aviso rojo: Ajustes de la app → Permisos → Ubicación → «Permitir mientras se usa la app» y «Ubicación precisa».
La ubicación se corta con el teléfono bloqueadoAjustes → Apps → GB Domicilios → Batería → «Sin restricciones».
El mapa no carga en la app del domiciliarioEn Google Cloud, agregar http://localhost/* a los sitios permitidos de la llave de Google Maps.
«App no instalada»El APK se hizo en otro computador o es más viejo: desinstalar la app e instalar de nuevo.

Al reportar un problema: qué hiciste, qué esperabas, qué pasó y una captura de pantalla.

10. Pendiente antes de usar staging y publicar

  • Desplegar a staging los cambios de las apps (incluye las migraciones 098 y 099). Hasta entonces, en staging las apps no conectan.
  • Firebase (sección 6), para las notificaciones con la app cerrada.
  • Llave de Google Maps: agregar http://localhost/*.
  • Google Play: cuenta (USD 25), llave de firma propia, política de privacidad y, para Domicilios, el formulario de ubicación en segundo plano. Con eso se puede usar la «prueba interna», que reparte la app y sus actualizaciones sin pasar archivos.
  • iPhone: después de Android; requiere cuenta de Apple Developer (USD 99/año).
